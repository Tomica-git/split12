## 1. 検証済みの事実（再調査は不要。E2E で再確認する）

Chromium 153（Chrome for Testing）と Playwright 1.63 で試作して確かめた結果です。設計はこれを前提にしてください。

- F1. Chrome には `chrome.runtime.getFrameId` が無い（Firefox 専用）。iframe 要素と extension の frameId の対応は、2.5 章の boot ページ方式で取る（動作確認済み）。
- F2. X-Frame-Options（XFO）や CSP `frame-ancestors` で拒否された iframe は、`chrome.webNavigation.onErrorOccurred` が `error === 'net::ERR_BLOCKED_BY_RESPONSE'` で通知する（frameId 付き）。サーバーが応答せずに接続を切った場合は `net::ERR_EMPTY_RESPONSE`。拒否された iframe でも、親ページ側の iframe の `load` イベントは発火する。
- F3. 3章の DNR セッションルールで、許可ドメインの XFO / frame-ancestors ページを表示できる。`tabIds` で絞るので、普通のタブでの埋め込み拒否はそのまま残る。許可していないドメインは、ペインの中に入れ子になった iframe でも拒否されたまま。許可したドメインは入れ子でも表示される。
- F4. `responseHeaders` 条件（値 `*frame-ancestors*`）で、frame-ancestors を含む CSP だけを消せる。含まない CSP は残る。消した CSP は script-src なども一緒に消える（既知の代償）。
- F5. iframe に `sandbox`（allow-top-navigation 系なし）を付けると、読み込み時の自動書き換え、クリックでの `top.location` 書き換え、`target="_top"` リンクのどれでも分割ページは置き換わらない。sandbox を外すと、ユーザー操作なしの `top.location = ...` だけで分割ページが別ページに置き換わる。
- F6. 親から `iframe.src = url` を代入すると、タブの履歴（全フレーム共通の履歴）が1つ増える。`iframe.contentWindow.location.replace(url)` と、新しく作った iframe の初回読み込みでは増えない。ペイン内でリンクをクリックすると増える。
- F7. ペインの中で `history.back()` を呼んでも、そのペインが戻るとは限らない（直近の履歴が別ペインのものだと何も起きなかった）。ペインごとの戻る・進むは自前の履歴で実装する。
- F8. 同じ iframe の中で遷移しても frameId は変わらない。
- F9. ペイン内のサイトには、ファーストパーティ扱いで Cookie が送られる（SameSite=Lax / Strict も送られる。`--test-third-party-cookie-phaseout` でサードパーティ Cookie をブロックした設定でも同じ）。localStorage もトップレベルで開いたときと共有される。ただし、ページの JS から `document.cookie` で見えるのは SameSite=None の Cookie だけ。
- F10. Playwright 既定のヘッドレス（headless shell）では拡張機能を読み込めない。`channel: 'chromium'` なら読み込める。ブランド版 Google Chrome は 137 以降 `--load-extension` を受け付けないので、E2E は Playwright 同梱の Chromium で行う。また Playwright は既定で `ThirdPartyStoragePartitioning` を無効にして起動するので、Cookie・ストレージの挙動は E2E では保証できない。
- F11. Chrome 本体の分割表示（Split View）は2枚までで、拡張機能向け API は Chrome 155 から（公式ブログの検索結果による。未精査）。今回は使わない。

### 2.3 画面

- 上部ツールバー: ビュー名、セッション一覧、ペイン数「1」〜「12」、向き・3＋1・四方向の追加、Undo/Redo、テンプレート、タブから追加、使い方、設定。ビュー追加はセッション一覧のプラスから、ショートカット変更は設定から行う。狭い画面では折り返す。
- ペイン: ヘッダー（高さ 32px 前後）と本体。ヘッダーには番号 / 枠のメニュー（R-85） / サイトアイコン / 戻る / 進む / 再読み込み / アドレス欄 / 表示倍率（R-13） / 新規ウィンドウへの移動 / 閉じる を置く。最大化は番号のダブルクリックで行う（R-44）。操作は `<button>` か `<input>` にし、日本語の aria-label を付ける（E2E は getByRole で操作する）。
- 空のペイン: アドレス欄と、今のウィンドウの http / https タブの一覧（アイコン・タイトル・ドメイン）。他のペインで表示中の URL と重複は除く。押すとそのペインで開く。候補が無いときは「上のアドレス欄に URL を入力してください。」を出す。
- 文言は日本語で、`src/ui/strings.ts` に集約する。主な文言:
  - 埋め込み拒否: 「{host} は埋め込み表示を拒否しています」。ボタン「このサイトを許可して再読み込み」「新しいタブで開く」
  - 許可済みなのに拒否された: 「{host} は許可済みですが表示できませんでした」。ボタン「新しいタブで開く」
  - 読み込み失敗: 「読み込みに失敗しました（{error}）」。ボタン「再試行」「新しいタブで開く」
  - 不正な入力: 「http または https の URL を入力してください」
  - 満杯: 「空いているペインがありません」
- 配色はシステムのライト / ダーク設定に従う（prefers-color-scheme）。最後に操作したペインは枠を強調する。

### 2.4 レイアウト

- 状態は `{ count: 1..12, orientation: 'landscape' | 'portrait', layout?: SplitTree, order?: number[] }`。landscape が「横並び」、portrait が「縦並び」。
- 段ごとの枚数（landscape は各行の枚数、portrait は各列の枚数）: 1:[1] 2:[2] 3:[3] 4:[2,2] 5:[3,2] 6:[3,3] 7:[4,3] 8:[4,4] 9:[3,3,3] 10:[4,3,3] 11:[4,4,3] 12:[4,4,4]。
- 純粋関数 `computeLayout(count, orientation)` が、CSS Grid の列数・行数と、各ペインの配置（row, col, rowSpan, colSpan）を返す。段ごとに枚数が違うときは最小公倍数の列数（行数）で割り付ける。例: 5枚 landscape は 6列×2行で、上段は colSpan 2、下段は colSpan 3。
- 初期・均等配置から二分木 SplitTree を作り、葉の実体IDを矩形へ変換して CSS の位置・幅・高さだけを変える。枝は x/y・比率・子2つを持ち、反転・リサイズ・葉の追加削除を表現する。
- 【重要】表示中の iframe を DOM の中で移動したり付け替えたりしない。12個のペイン要素を grid 直下に固定し、サイドバーもフレーム生成前に配置する。表示番号は `order.indexOf(slot)+1` でラベルだけ変える。非表示で iframe が無い枠同士の保存データ・履歴の交換だけは、既存の追加・保存契約を保つため許可する。
- count を減らしたときは、範囲外のペインの iframe を破棄して隠す。URL は状態に残し、count を戻したら読み込み直す。
- 最大化: 対象ペインがグリッド全体を占め、他のペインは CSS で隠すだけにする（破棄しない）。最大化の状態は保存しない。

### 2.5 ペインの読み込みと遷移

- 拡張機能側から行うペインの読み込み（URL 入力、戻る / 進む、再読み込み、許可して再読み込み、復元）は、すべて「iframe を作り直し、boot ページ経由で読み込む」1つの経路で行う。
  - `iframe.src = chrome.runtime.getURL('pane-boot.html?pane=<paneId>&nav=<連番>&to=' + encodeURIComponent(url))`
  - `pane-boot.html` は拡張機能内のページで、`to` が http / https のときだけ `location.replace(to)` する。それ以外は何もしない。
  - iframe を作り直すのはペイン要素の中だけで、ペイン要素（grid の子）は動かさない。
- split ページで `chrome.webNavigation.onCommitted` を購読し、boot ページの URL を見つけたら `frameId → paneId` を記録する。同じペインで nav が古いものは無視する。以後その frameId の onCommitted / onHistoryStateUpdated / onReferenceFragmentUpdated / onErrorOccurred をそのペインに結びつける。自分の tabId 以外のイベントは捨てる。
- iframe の属性:
  - `sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox allow-modals allow-downloads"`。allow-top-navigation 系は絶対に入れない（F5）。
  - `allow="fullscreen; autoplay; clipboard-write; encrypted-media; picture-in-picture"`
- 戻る / 進むは自前の履歴（純粋関数のリデューサ `paneHistory`）で管理し、`history.back()` は使わない（F7）。
  - 通常のコミット: 現在位置より先を捨てて追加する。直前と同じ URL なら追加しない。
  - 自分のボタンによる移動（traverse の意図を持たせて読み込む）: 位置だけ動かす。リダイレクトで URL が変わったら、その項目を置き換える。
  - ブラウザ自体の戻る / 進む（transitionQualifiers に `forward_back`）: 隣の項目と URL が一致すれば位置だけ動かし、一致しなければ追加する。
  - 1ペイン最大50件で、古いものから捨てる。履歴は保存しない。
- エラー: `net::ERR_ABORTED` は無視する。`net::ERR_BLOCKED_BY_RESPONSE` は埋め込み拒否として扱う。それ以外は読み込み失敗として扱う。表示はペイン上のオーバーレイ（2.3 の文言）。

### 2.6 埋め込み許可リスト

- 許可リストは正規化したホスト名の配列。DNR の `requestDomains` に入れるので、サブドメインも対象になる。
- 正規化 `normalizeHost`: URL として解釈して hostname を取り（小文字化と punycode 化は URL API に任せる）、先頭の `www.` を1つ除き、末尾の `.` を除く。IPv6 リテラルと空文字は null。
- ユーザーが明示的に開いた URL（アドレス欄、R-11、R-12）のホストは自動で許可リストに入れる。ペイン内のリンク遷移と、保存済み URL の復元では自動で入れない（設定で削除したホストが復元で戻ってしまわないようにする。拒否されたらオーバーレイから許可してもらう）。
- 設定ダイアログ（split ページ内の `<dialog>`）で一覧・削除できる。削除しても、開いているペインはそのまま（次の読み込みから効く）。

### 2.7 状態と保存（正本と書き手をそれぞれ1つにする）

| 状態 | 置き場所 | 書き手（唯一） |
|---|---|---|
| workspace（layout・order・固定枠と12枠の URL・表示倍率） | storage.local `workspace` または `workspace:<viewId>`（schemaVersion: 1） | 対応する split ページ |
| ビュー一覧・登録順 | storage.local `viewRegistry`（schemaVersion: 1、views配列） | Service Worker |
| 削除済みビューID | storage.local `viewTombstones`（schemaVersion: 1） | Service Worker |
| 配置テンプレート | storage.local `layoutTemplates`（schemaVersion: 1） | Service Worker |
| サイドバー表示 | storage.local `ui`（schemaVersion: 1、sidebarVisible） | 利用者が操作した split ページ |
| 許可リスト | storage.local `allowlist`（schemaVersion: 1） | Service Worker |
| 分割タブの tabId | storage.session `splitTabId` と `splitTabIds` | Service Worker |
| DNR セッションルール | 保存しない。許可リストと splitTabId から毎回作る | Service Worker |
| frameId の対応、ページ履歴、構造Undo/Redo、エラー表示、最大化、境界選択 | split ページのメモリ | split ページ |

- 書き手以外は直接書かず、メッセージで書き手に頼む。
- workspace は必ず純粋関数 `parseWorkspace(unknown)` を通して読む。壊れている、型が違う、未知の schemaVersion のときは既定値（count 4、landscape、全ペイン空）で起動し、クラッシュしない。不正な URL はその枠だけ空にする。
- workspace は変更のたびに保存する。タブを閉じる直前の変更が失われないようにする。
- 旧8枠は12枠へ補完する。省略・不正な `order` は恒等順列に戻し、不正な layout は使わない。panes と layout の葉は実体ID基準で保存する。
- ビュー一覧は既存保存キーと登録済みの拡張タブから移行する。タブの生存は `tabs.get/query` で url と pendingUrl を検証し、一覧の書き込みは SW の直列キューで行う。閉じても保存データは消さない。

### 2.8 メッセージの契約（型は `src/shared/messages.ts` に定義する）

- split → SW `{ type: 'split/register' }`: 登録タブ集合へ追加し、DNR 適用後に `{ ok: true, tabId }` を返す。新規ビューは `split/create`。`views/register` で同じ ID の生存タブがあれば、作成したコピーの `forkUrl` へフレーム生成前に移動する。
- split → SW `views/list`、`views/focus {id}`: 自身の拡張ページ・frameId 0・登録タブ・現在 URL を検証する。focus は既存のタブを前面にするか、保存済み ID で再開する。
- split → SW `{ type: 'allowlist/add', hosts: string[] }` と `{ type: 'allowlist/remove', hosts: string[] }`: ルールを適用し終えてから `{ ok: true, hosts: 現在の許可リスト }` を返す。
- SW → split（runtime.sendMessage）`{ type: 'pane/add-url', tabId, url, axis?, frameId? }`（R-11）。分割タブが無いときは `split.html?add=<encodeURIComponent(URL)>&axis=<x/y>` で開き、split 側は処理後に `history.replaceState` でパラメータを消す。
- サイト内の操作キーは `app/config` / `app/pressed`、信頼されたクリック・キーボード操作は `app/activate`。SW が現在の documentId と親フレームを確認して `app/action {tabId,action,frameId,at}` または `pane/activate {tabId,frameId,at}` を返す。split は SW からの通知だけを受け、自身の tabId と現在の nav が一致する枠だけを操作し、遅延した入力で新しい選択を上書きしない。`about:blank` / `about:srcdoc` の子フレームもhttp(s)の直接ペインまでの祖先関係を検証した場合だけ扱う。URLを開く入口は引き続きhttp(s)に限る。
- split ページは、register の ok を受け取るまで iframe を1つも作らない（ルールより先に読み込みが始まるのを防ぐ）。許可して再読み込みも、allowlist/add の応答を待ってから読み込む。
- SW は、sender.id が自分自身で sender.url が split.html のメッセージだけを受け付ける。
- SW は tabs.onRemoved で分割タブが閉じたら splitTabId を消してルールを外す。tabs.onUpdated で split.html 以外に移動したときも同じ。
- アイコンのクリック（action.onClicked）とショートカット: 操作したタブと同じウィンドウに新しい独立ビューを開く。

## 4. セキュリティの約束（破ったらテストが落ちるようにする）

- S-01 ヘッダーの除去は、分割タブの sub_frame だけに効く（tabIds を持たないルールを作らない）。普通のタブでの埋め込み拒否は変わらない。
- S-02 許可リストにないドメインは、ペインの中に入れ子になった iframe でも XFO / CSP の保護が残る。
- S-03 ペイン内のページが、分割ページ全体を別ページに置き換えられない（自動、クリック、target=_top のどれでも）。
- S-04 CSP は frame-ancestors を含む場合だけ除去する。
- S-05 manifest に web_accessible_resources と externally_connectable を書かない。リモートのスクリプトを読み込まない。eval や new Function を使わない。
- S-06 開ける URL は http / https だけ。アドレス欄、boot ページ、復元、右クリック、タブから追加のすべての入口で確かめる。
- 既知の代償（README に書く）: 許可したサイトは、分割タブの中では他のサイトからも埋め込める状態になる（クリックジャッキングへの耐性が下がる）。CSP に frame-ancestors があるサイトは、分割タブの中では CSP 全体が外れる。


- R-68 分割枠内のリンクで開いた新しいタブは自動取り込みせず、元の枠と新しい通常タブを保持する。手動のタブ追加と右クリック追加は維持する。
- R-69 固定枠の上下左右への追加を Chrome のショートカット設定に登録可能にする。Mac のビュー内では ⌘⇧W/A/S/D をそれぞれ上/左/下/右として扱う。ただし Chrome や OS が優先するキーは届かない場合がある。⌘⇧D の既存の枠削除割当は右追加に変更し、枠削除はボタンや変更可能なコマンドで利用する。
- R-70 上部の左側はセッション一覧、表示数、四方向追加、戻す・やり直し、一覧、横並び・縦並びの順に並べる。

- R-71 セッション一覧の右上の×で一覧を閉じ、「追加」は操作対象の「開く」「削除」の右に配置する（0.1.97f でその右に「編集」を追加）。追加は従来どおりビューを保存するだけで開かない。
- R-72（0.2.0f で R-93 に置き換え）拡張機能ボタンは押したタブの隣に別の独立ビューを作り、現在のウィンドウで開く。既存のビューは保持する。
- R-73 現在のビューのタブ一覧で順序を変えると番号のみを順送りし、ページと枠の位置、状態を保持する。Undo・Redo・保存に対応する。
- R-74 四方向追加ボタンを右クリックするとリンク追加の方向を固定・切替・解除し、選択中を表示する。固定設定は保存し、リンクを分割ビューに追加する際、固定枠を指定方向に分割する。個別の明示的な方向指定が優先される。
- R-75 分割ビューの最後のタブを閉じたとき、表示中と非表示を含む全12枠が確実に空なら、そのビューを一覧と保存から自動削除する。URLが1つでも残る場合、読み込み準備中、別のタブで同じビューが開いている場合、または空の状態を確認できない場合は残す。
# R-79 リンクを分割位置にドロップして追加（2026-11-10 の利用者決定で改訂）

- URL のドロップは、境界線・枠の辺・外周・固定タブの専用ゾーン・読み込み済みの枠の中央と見出しのどこでも、既存の枠とページを保持したまま新しい枠を1つ追加して URL を開く。中央と見出しは固定タブと同じ追加方向（四方向ボタンの右クリックで固定した方向、未設定は右）でその枠を分ける。
- 読み込み済みの枠はどの操作でも置き換えない（2026-11-10 の利用者決定で Shift の置き換えも廃止）。空の枠の中央に落とした場合はその枠で開き、枠は増やさない。
- URL ドラッグ中は固定タブの追加方向側に「固定タブの○に追加」の専用ゾーンを表示し、落とす前の位置をプレビューで示す。
- URL は `text/uri-list`、HTML のリンク先、本文の順に解釈する。リンクのない画像、交点、無効な URL、最大数・最小サイズ超過は追加せず理由を表示する。ツールバー・セッション一覧など対象外の位置では何も起きず、分割ビューのタブも移動しない。
- ページ側の検知は捕捉フェーズで行い、ページが伝播を止めても覆いを出す。覆いより先にページへ落ちた URL ドロップは、ページ内のスクリプトがページの既定処理を止めたうえで拡張機能の裏方へ中継し、分割画面が落とした位置から追加先を決める。ページ自身が処理したドロップは中継しない。
- 左下に「ドラッグ診断」を次のドラッグまで表示し、版番号・検知経路・受信した種類・受信件数・判定した先・結果を確認できる。
- URL ドラッグ中の表示は数字のドラッグと同じにする（0.1.95f）。重ねた境界線は青、交点は赤、新しい枠の位置は色付きのプレビューで示す。落とした後は表示数を1つ増やし、最後の番号の枠を落とした位置に配置して URL を開く。
- Mac 実機の X のリンクカードでの検証は未完了。キャンセルとの区別が検証されていない dragend 座標だけで勝手に追加しない。
- （2026-11-10 確定）Chrome は同じタブ内でサイトをまたぐネイティブのドラッグを遮断する（Chromium `WebContentsViewDragSecurityInfo::IsValidDragTarget`、crbug.com/59081・666858）。枠のページから分割画面や別サイトの枠へのネイティブなドロップは実機では届かないため、枠内のリンクは R-80 の模擬ドラッグで扱う。タブ外（別ウィンドウ・ブックマーク・Finder）からのドロップはこの節のとおり受け取る。

# R-80 枠内のリンクは模擬ドラッグで枠を追加（0.1.96f）

- 枠のページ内で http/https のリンク（画像つきを含む）をつかむと、ページ側スクリプトが Chrome のネイティブなドラッグを取り消し、開始位置・URL・表示名を分割画面へ知らせる。分割画面は数字のドラッグと同じ覆い・プレビュー・境界線と交点の強調・専用ゾーン・URL の付箋を出し、ポインターを自分で追跡する。
- 離した位置の扱いは R-79 と同じ（境界線・枠の辺・外周・専用ゾーン・別の枠の中央は追加、空の枠はその枠で開く、ツールバーなど対象外は何もしない）。元の枠の中央で離した場合と Esc は中止し、リンクのクリックにもしない。
- ドロップは、同じ id と URL の開始通知をページ側スクリプトから拡張機能の裏方経由で確認できた場合だけ適用する。ページの postMessage だけでは追加しない。開始通知の到着を最大 0.8 秒待つ。
- Shift を押しながらつかんだ場合はネイティブのドラッグのままにする（別ウィンドウへ持ち出す用）。ページ自身が draggable にした要素の中のリンクも、ページの機能を壊さないようネイティブのまま。
- 入れ子フレームのリンクは、裏方の確認が届いた時点で模擬ドラッグを始める。ドラッグ状態は 20 秒無操作、別のポインター押下、ウィンドウの blur で中止する。
- 自動テストは実マウス操作で検査する。CDP の `Input.dispatchDragEvent` は Chrome の遮断判定を通らないため、タブ外からのドロップの検査にだけ使う。
